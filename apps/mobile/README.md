# Drowzi mobile

Expo (SDK 54) + Expo Router + TypeScript. See repo `docs/` for product and system design.

## Run

```bash
cd apps/mobile
npm install
npm run start
```

- **typecheck:** `npm run typecheck`

## Development build (USB Android)

This app uses **`expo-dev-client`** (camera / MediaPipe / notifications). Expo Go is not enough for the full native stack. Package id: `com.anonymous.drowzi`.

**One-time install on a physical phone**

1. USB debugging on; confirm the device:
   ```bash
   adb devices
   ```
   (`adb` lives in Android SDK `platform-tools` — add it to PATH, or use `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`.)
2. Set JDK for Gradle (Android Studio JBR works):
   ```powershell
   $env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
   $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
   $env:Path = "$env:ANDROID_HOME\platform-tools;$env:JAVA_HOME\bin;$env:Path"
   ```
3. Build + install **without** starting Metro (avoids port 8081 fights):
   ```bash
   npm run android:device
   ```
   With a single USB device attached, Expo installs to that phone. Prefer model name over adb serial if you must pass `-d` (e.g. `-d Infinix_X6731`).
4. First compile can take several minutes (vision-camera, MediaPipe, reanimated). Later rebuilds are incremental.
5. **Do not** run `npx expo prebuild --clean` unless native plugins/deps changed. Keep the local `android/` folder.

**Day-to-day after the APK is installed**

```bash
npm run adb:reverse   # once per USB reconnect
npm run start:usb     # Metro on localhost
```

Open the **Drowzi** app on the phone (or press `a` in Metro). It should connect to Metro over the reverse tunnel.

Gradle is already tuned for phone-only ABI (`arm64-v8a`) and capped workers in `android/gradle.properties`.

**Faster cold rebuilds.** `android/` is regenerated by prebuild, so per-repo gradle tweaks get wiped. Put the build/config cache in your *global* Gradle config instead — machine-wide, survives every prebuild, no repo change:

```properties
# ~/.gradle/gradle.properties  (Windows: %USERPROFILE%\.gradle\gradle.properties)
org.gradle.caching=true
org.gradle.configuration-cache=true
org.gradle.parallel=true
```

This makes unchanged native modules (vision-camera, MediaPipe, reanimated) restore from cache instead of recompiling. If you later want this committed/reproducible for the team, move it into `app.json` via `expo-build-properties` (adds a dependency).

## Expo Go (limited — JS-only debugging)

Metro may pick a **bad Windows IP** (e.g. `172.24.*` from Hyper-V/WSL). Your phone then cannot load `exp://172.24.x.x:8081`.

**USB Android:**

1. `npm run adb:reverse` once per reconnect.
2. `npm run start:usb` (or `npm run start:usb-go` if that script exists).
3. Open in Expo Go — native modules (camera / Nitro) will not work fully.

**Wi‑Fi instead:** Use `npm run start:tunnel` or set your real Wi‑Fi IPv4:

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME = "192.168.x.x"
npm run start
```

**Also:** Pressing `w` only opens **web**; ignore `[web]` logs when debugging on device.
